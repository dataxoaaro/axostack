### Prototype

**A throwaway sketch to settle a question cheaply. Observing beats asking.**

1. Name the question the prototype answers and the observation that decides it. No question, no prototype.
2. About to ask the user a "which approach" or "how should this behave" fork → classify it first. If the answer is observable (behavior, timing, layout, output, perf), it is not the human's to answer. Build the probe and let the result decide. Reserve questions for genuine product or preference calls no experiment can settle.
3. Build via the `prototype` skill: a single shareable HTML file for state and logic questions, or toggleable variations for UI questions. TDD does not apply here. Prototype code is exempt from production standards and never merges.
4. Record the answer, then delete the sketch or park it clearly marked as throwaway.
5. The decision feeds the real work: re-enter **Feature** with the answer in hand.

**Reply:** the question, the observation, the decision it drove.
